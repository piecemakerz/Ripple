# Astra 중심 개발 운영

이 프로젝트의 세팅 목표는 패키지 설치뿐 아니라 AI가 맥락을 유지하며 작은 기능을 끝까지 구현·검증하는 것이다. 사용자 역할은 제품 판단과 사용성 피드백이며, 일상적인 구현·디버깅·기록 갱신은 AI가 담당한다.

## 시작

`npm run ai`는 현재 저장소에서 Astra/high를 명시한 Codex를 실행한다. `npm run ai:check`는 CLI/로그인만 확인한다. 현재 데스크톱 대화를 전환하는 명령이 아니며, 실제 모델 호출이 성공했다고 추정해서는 안 된다. 계정이 Astra를 지원하지 않으면 오류를 알리고 다른 모델로 조용히 대체하지 않는다.

새 세션은 순서대로 `AGENTS.md` → `docs/STATUS.md` → `docs/PLAN.md` → `docs/ARCHITECTURE.md`를 읽고 필요한 범위만 원본 명세에서 찾는다. 명세/코드/테스트가 어긋나면 실제 현황과 미해결 차이를 기록한다.

Relate 작업 전에는 `npm run relate:context`를 실행하고 출력된 공식 Node/TypeScript 스킬과 설치된 타입 정의를 읽는다. Astra 런처는 이 사전 검사를 자동 실행하고 해당 스킬을 읽도록 시작 프롬프트에 포함한다. 이 명령은 일회성 메모리 DB의 매개변수 조회만 수행하며 라이브 DB나 모델을 호출하지 않는다. 공식 CLI의 `relate agent-context`와는 다른 프로젝트 명령이다. 네 공식 참고 자료의 적용 결정은 [RELATE_RESOURCES.md](RELATE_RESOURCES.md)에 있다.

## 작업 루프

관련 작업에만 프로젝트 스킬을 사용한다: DB/Cypher는 `relate`, React는 `vercel-react-best-practices`, UI 검토는 `web-design-guidelines`, 중요한 변경의 검증은 `ripple-verify`. 전체 스킬 본문을 매번 읽지 않는다. `npm run ai:doctor`로 설치 상태를 확인하고, 공개 후에는 `npm run ci:status`로 정확한 커밋의 결과를 확인한다. [설치 출처와 도구 상태](AI_TOOLING.md)

1. 사용자 요청을 현재 승인된 범위와 연결하고 완료 기준을 3~5개로 구체화한다. 핵심 데이터 변경은 실패·재시작 기준도 포함한다.
2. Git 상태와 영향을 받는 코드를 읽는다. 사용자 변경과 현재 DB를 보존한다.
3. 설계 선택의 이유와 불변 조건을 짧게 기록한다. API·DB·UI가 이어지는 한 흐름을 구현한다.
4. 위험에 맞는 검증을 실행한다. 핵심 기준은 `npm run verify`; DB/런타임 변경은 `npm run doctor`도 실행한다. 화면 변경은 실제 브라우저로 검증한다.
5. 실패를 고치고 변경과 관련된 검사만 다시 실행한다. 코드가 같고 이미 통과한 검사를 의미 없이 반복하지 않는다.
6. 마지막에 영향 방향, 원문 보존, 트랜잭션, 중복 요청, UI 오류 보존을 스스로 리뷰한다. 사용자가 요청하지 않은 하위 에이전트나 외부 유료 API를 실행하지 않는다.
7. `STATUS.md`에 검증 명령·결과·미완료·다음 작업을 갱신하고 `PLAN.md`에 실제 완료 상태를 반영한다. 사용자에게 확인할 화면과 실행 방법을 남긴다.

## 다음 세션용 요청 예시

```text
AGENTS.md와 docs/STATUS.md, docs/PLAN.md를 읽고 현재 구현을 확인해주세요.
다음 승인된 작업은 [구체적 범위]입니다.
완료 기준은 [관찰 가능한 행동과 실패 조건]입니다.
실제 Relate를 사용해 구현하고 관련 테스트와 브라우저 확인까지 수행한 뒤,
검증 결과와 미완료 항목을 docs/STATUS.md에 갱신해주세요.
```

M2를 승인할 경우 먼저 **문서 입력 → 불변 SourceVersion 저장 → 정확한 인용 위치 확인**을 키 없이 완성한다. 모델 추출은 공급자·예산·비밀 키 관리가 확정된 뒤 후보로 연결한다. 모델 출력이 confirmed 관계가 되거나 영향 목록을 직접 생성하게 만들지 않는다.

## 완료의 의미

“코드 작성됨”과 “검증됨”을 구분한다. 설치 성공은 런타임 성공이 아니며, 빌드 성공은 브라우저 동작이 아니다. 프로세스 내 재조회는 재시작 복원이 아니다. 설정 파일의 모델 ID는 현재 세션 모델 확인이 아니다. 이 구분을 완료 보고와 상태 문서에 일관되게 유지한다.

## 권한과 비용

일상적인 로컬 구현·테스트·문서화는 승인된 작업 안에서 계속한다. 예산이 필요한 외부 AI 추출, 공개 배포, 외부 서비스 연결, 실제 자료 업로드, 파괴적 변경은 기존 사용자 권한의 범위를 확인한다. 개발용 Astra 선택과 앱의 AI 추출 API는 별개이며 M0/M1 앱은 API 키 없이 실행된다.
