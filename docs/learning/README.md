# 해커톤 판단과 학습 기록

Ripple에서 어떤 문제를 선택했고, 어떤 근거로 시간을 배분했으며, 실제 결과가 기대와 어떻게 달랐는지를 보존한다. 수상 여부가 나온 뒤 다음 해커톤의 행동을 개선하기 위한 기록이다. 시작일은 2026-11-15 KST다.

기록 대상은 **판단 근거, 가정, 대안, 선택, 예상 결과, 검증 결과를 요약한 의사결정 기록**이다. 모든 대화의 원문이나 기록되지 않은 과거 생각을 복원한 자료가 아니다. 과거는 확인 가능한 문서에서만 복원하며, 당시의 확신·소요 시간·검토한 대안이 없으면 미기록으로 남긴다.

## 앞으로 남기는 방법

1. 제품 방향·대상 사용자·기술·범위·제출 전략·큰 시간 배분을 바꾸기 전에 결정 ID를 만들고 당시 정보, 실제 비교한 대안, 예상 결과와 재검토 조건을 짧게 적는다. 단순 오탈자마다 기록하지 않는다.
2. 가설을 검증하기 전에 대상, 방법, 성공·실패 기준을 적는다. 수치 예측의 근거가 없으면 정성 기준을 사용한다. 실제 시간·도움·준비 비용은 관측한 만큼만 남긴다.
3. 작업 종료 시 명령·관찰·실패·미실행을 기존 STATUS/QA와 연결하고, 예측과 다른 결과를 덧붙인다. AI 제안, 사용자의 명시적 결정, 위임 범위 안의 실행, 독립 사용자의 피드백을 구분한다.
4. 결정을 뒤집을 때는 이전 기록을 지우지 않고 날짜와 새 결정 ID로 연결한다. 사후 해석은 별도 후속 기록에 넣는다. 결과 발표 후 작성한 가설을 사전 예측처럼 바꾸지 않는다.
5. 제출 직전에는 실제 제출 코드·데이터 버전, 문구, 영상, 공개 접근 확인, 제출 완료 증거를 고정한다. 커밋이 없는 변경은 별도로 표시한다. 공유 전 개인정보·비밀·비공개 피드백을 검토한다.
6. 수상·미수상 어느 경우든 [회고 양식](RETROSPECTIVE.md)을 채우고, 다음 대회에 적용할 규칙은 최대 세 개부터 선택한다.

이 지침은 이후 이 저장소에서 작업할 때 기록을 이어가기 위한 것이다. 별도 자동 수집기나 일정 작업은 설치하지 않았다. 다른 프로젝트에는 [양식](TEMPLATE.md)의 시작 지침을 복사해야 하며, 과거 다른 채팅을 자동 수집했다고 가정하지 않는다. 파일은 로컬에 작성되었으며 이번 작업에서 커밋·원격 백업·게시하지 않았다.

## 현재 가장 중요한 미확인 사항

- 작은 제품팀이 이 문제를 실제로 얼마나 자주 겪고, 현재 방식보다 Ripple을 사용할 의향이 있는가.
- 사람이 문서와 관계를 준비하는 비용까지 포함해 영향 누락이나 검토 시간을 줄이는가.
- 처음 보는 사람이 샘플에서 자기 문서 검토로 넘어가고, 저장된 결정과 구현 완료를 구분하는가.
- 심사자가 짧은 데모만으로 연결된 맥락의 효용과 기존 도구와의 차이를 이해하는가.
- 최종 제출물·공개 영상·접근 가능성이 실제로 확인되었는가.

이것들은 확인할 가설이다. 현재의 결함이나 미래 미수상의 원인으로 확정하지 않는다.
