# Ripple 의사결정 기록

## D21 검증본의 공개 브랜치·초안 PR·릴리스 — 2026-11-26

- **사용자 결정:** 검증본을 GitHub 새 브랜치와 초안 PR로 공개하고 ZIP·영상을 릴리스로 게시하도록 명시적으로 승인했다. main 병합과 Devpost 접수는 이 승인에 포함시키지 않는다.
- **근거:** D20의 현재 작업본/새 설치 91개 검사, 실제 UI와 native 복원, 영상·ZIP 무결성 검증이 완료됐다. 공개 main은 이전 e7d28a7이라 심사 접근의 차이가 남아 있다.
- **위임된 선택:** `codex/hackathon-verified-20261126` 브랜치와 draft PR, `v0.1.0-hackathon.20261126` 공개 prerelease로 전달한다. 안정판으로 오인되지 않게 후보 상태를 표시하고 기존 ZIP/영상 바이트를 유지한다. 패키지의 과거 준비 metadata와 새 공개 커밋은 별도의 배포 대응 기록으로 연결한다.
- **대안·비용:** main에 직접 반영하면 검토 경계를 없애므로 선택하지 않는다. 기존 ZIP을 몰래 다시 만들면 사용자가 승인한 hash가 바뀌므로 유지한다. 문서의 공개 상태 갱신과 Git 줄바꿈 정규화 차이는 명시하고 앱/검사/fixture의 대응을 검사한다.
- **검증·불확실성:** 새 커밋의 CI, draft 여부, 릴리스 첨부 hash와 인증 없는 다운로드를 확인한다. 공개 접근은 효용·수상·제출 완료의 증거가 아니다. 공개 도구 오류가 있으면 원인과 재시도를 기록하고 기존 전달물을 덮어쓰지 않는다.

## D20 비판적 검토 후 실제 개선 — 2026-11-26

- **사용자 결정:** 검토의 개선 작업을 요청했고 효용 사례는 Ripple 자체 변경으로 진행하도록 선택했다.
- **근거:** D19의 stale review 덮어쓰기는 native API로 재현됐다. 새 원문 표시가 없고, 기존 영상은 첫 장면 잘림·63초 이후 판단으로 실제 결과 전달이 약했다. 최신 공개본과 로컬본도 다르다.
- **위임된 선택:** 검토 revision과 request ID를 서버에서 강제하고 충돌 시 초안을 보존·비교하게 한다. 새 원문 신호는 보존된 경로의 사실과 분리한다. 이번 API 변경의 실제 호출자와 실행 묶음 의존성을 동결한 코드 인용으로 모델링하고, 개발자 사례로 명시한다. 이를 중심으로 새 데모와 일치하는 로컬 전달물을 만든다.
- **대안·비용:** 자동 의미 추출·추가 그래프 장식은 이번 결함을 해결하지 않으며 평가 비용을 늘린다. revision 도입은 모든 호출자와 구버전 저장소 호환 검증이 필요하다. 수동 그래프 작성 비용은 숨기지 않는다. 공개 업로드가 필요한 경우 구체적인 검증된 전달물이 준비된 뒤 처리한다.
- **불확실성과 재검토:** 자체 사례는 고객 수요·독립 인간 검증이 아니다. 실제 누락을 새로 발견했다고 소급 주장하지 않는다. 관계가 코드 인용으로 뒷받침되지 않거나 준비 비용이 이익보다 크면 사례 범위와 효용 주장을 줄인다.

## D19 수상 충분성의 비판적 재검토 — 2026-11-26

- **사용자 요청:** 지난 개선 이후 수상하기에 충분한지 종합적이고 비판적으로 재검토한다. 이번 작업은 제품/제출 평가이며 추가 기능 구현·공개 접수 요청으로 확대하지 않는다.
- **현재 근거와 공백:** 로컬 84-test gate와 실행 묶음은 검증됐지만 독립 사용자 효용·공개 최신본·최종 제출은 확인되지 않았다. 공식 갤러리에서 영향 분석과 원문 근거를 전면에 내세운 다른 제출물이 관측돼 차별화 주장을 다시 검토할 필요가 있다.
- **선택과 대안:** 같은 성공 테스트를 반복하는 대신 현재 공개 규정·유사 제출물의 공개 자료, 실제 첫 사용/개인 준비 화면, 데이터 의미와 데모의 설득력을 대조한다. 경쟁자의 자기소개와 직접 실행 증거를 구분하고 인간 검증·심사 점수·순위를 생성하지 않는다. 스크린리더의 사용자 수락 범위는 다시 열지 않는다.
- **예상·비용·불확실성:** 기술 검증과 상위 3개 선정에 필요한 제품 증거의 차이를 밝히고 우선순위를 좁힌다. 읽기·화면 캡처·격리된 진단 비용이 들며 모든 경쟁작의 구현을 평가하거나 승률을 산정할 수는 없다.
- **재검토 기준:** 실제 경쟁작 비교·새 결함·사용자 관측이 이전 평가를 반박하면 이전 기록을 보존한 채 정정한다. 제품 코드와 기존 제출 후보 ZIP은 감사 중 변경하지 않는다.

### D19 관측과 판단 보정 — 2026-11-26

유사 공개 출품작이 경로·원문·영구 DB 검사까지 제시하고 있어 그 조합만으로 충분한 차별성이라고 보지 않는다. 비교는 공개 설명/일부 source 읽기이며 경쟁작의 실행 성공·심사 결과는 미확인이다. 현재 UI·다운로드는 동작했지만 준비 비용은 여전히 미측정이다. Native API에서 표현 변경과 일정 변경의 동일 후보, 오래된 검토 요청의 덮어쓰기, 새 원문 이후 v1 근거 유지가 확인됐다. 마지막 두 항목은 각각 저장 보호와 자료 유지의 다음 과제다.

이전 영상 완성은 생성·디코딩·일부 프레임 검사 완료로 한정한다. 이번에 첫 장면의 그래프 잘림과 완료→미적용 순서, 63초 이후 첫 판단이라는 전달 약점을 확인했다. 형식 자체는 공식적으로 허용된다. [비판적 보고서](../HACKATHON_CRITICAL_REVIEW_2026-11-26.md)는 “기술적 MVP”와 “상위 3개로 선택할 충분한 근거”를 분리하고, 아직 후자를 충족했다고 판단하지 않는다. 실제 인간 효용과 수상 결과는 여전히 미확인이다.

## D18 심사 재현성과 제출 증거 보강 — 2026-11-26

- **권한:** 사용자가 최신 해커톤 기준의 종합 평가와 부족한 부분의 개선을 요청했다. 로컬 구현·검증·제출 자료 준비를 진행하며 공개 업로드와 최종 접수는 별도 상태로 남긴다.
- **관측:** 공식 Rules가 11월 24일 개정되어 배점은 연결된 맥락 30 / 기능 25 / 유용성 20 / 문서·재현 15 / 창의성 10으로 일치한다. D05의 배점 불일치는 해소됐다. 기존 프로젝트 허용 문구의 차이는 남아 있어 신규 개발 이력을 보존한다. 최신 UI는 작업 트리에 있고 공개 HEAD는 11월 14일이다. SemVer 실행도 기본 재고 사례에서 시작한다. 공개 영상과 실제 접수 증거, 독립 인간 효용 검증은 없다.
- **선택:** 사례·검토를 바로 여는 복원 가능한 URL, 닫힌 합성 저장소의 읽기 전용 검사와 재현 가능한 제출 묶음, 최신 실제 화면의 데모 자료를 우선한다. 기존 핵심 동작·데이터 모델은 유지한다.
- **실제 대안:** 자동 관계 추출은 수동 준비 부담을 줄일 가능성이 있으나 공급자·비용·의미 평가가 필요하다. 새 시각 디자인은 이미 반복 검증한 흐름을 다시 바꾼다. 현 단계에서는 심사자가 현재 구현을 재현하는 데 드는 마찰과 필수 제출물 공백을 먼저 줄인다.
- **기대·비용·불확실성:** 첫 진입의 혼란과 자료 버전 불일치를 줄일 것으로 예상한다. 도구·회귀 검사·녹화 준비 비용이 들며 실제 사용자 시간 절감이나 수상을 보장하지 않는다. 인간 피드백은 생성하거나 대체하지 않는다.
- **재검토:** 새 환경 실행 실패, 현재 화면으로 핵심 효용 전달 실패, 실제 사람의 준비 비용 관측 시 해당 병목을 다음 우선순위로 올린다. 공식 출처는 [메인](https://relate.devpost.com/)과 [Rules](https://relate.devpost.com/rules).

### D18 후속 결과 — 2026-11-26

직접 사례/검토 링크와 재현 묶음을 구현했고 실제 새 설치·84개 검사·브라우저 저장/재시작을 통과했다. 영문 자막형 110초 로컬 영상도 준비했다. 실제 검증이 샘플의 분리된 선택 상태와 초기 영상 자막 겹침을 드러내어 수정했다. 연속 녹화, 독립 인간 사용 또는 시간 절감으로 표현하지 않는다. [X18](EXPERIMENTS.md)의 결과는 로컬 재현을 지지하지만 공개 접근과 제출, 실제 제품 가치는 별도로 남는다. 추가 기능보다 공개 전달과 준비 비용을 포함한 대상 사용자 관찰을 다음으로 유지한다.

## D17 실제 확대·스크린리더와 첫 사용 흐름 재검증 — 2026-11-25

- 사용자 결정: 남은 200% 확대와 스크린리더 검증을 끝내고 초심자 전체 흐름의 문제를 개선하라는 요청 및 연결 재확인 요청.
- 근거: D16의 좁은 화면·접근성 트리 관찰은 실제 확대/음성 출력의 증거가 아니다. 이전 연결 차단 이후 이번에는 Chrome 연결과 전용 창을 확인했다.
- 위임된 실행 선택: 임시 Relate 저장소에서 Chrome의 실제 확대 표시와 Windows 내레이터의 음성 기록을 관찰한다. DOM/정적 검사만 하는 대안보다 실제 포커스·읽기 문제를 확인할 수 있다.
- 예상 결과·비용: 핵심 과업을 확대와 키보드/읽기로 수행하고 재현된 문제만 수정한다. 추가 수동 검증 시간이 들며 한 브라우저·한 보조기술의 결과다. 독립 사용자의 이해도나 모든 WCAG 기준 통과로 확대 해석하지 않는다.
- 재검토 조건: 실제 음성 기록을 얻지 못하면 미검증으로 명시한다. 개인 데이터·실사용 저장소는 사용하지 않고 기존 디자인·API 계약을 유지한다.

### D17 후속 관측과 사용자 완료 수락 — 2026-11-25

실제 Chrome 200% 표시와 내레이터 음성 요약을 확인했다. 단일 선택을 토글로 읽는 문제, 확대 시 판단 대상 문장 숨김, 접힌 이유 예시의 강제 읽기, 비동기 원문을 닫은 뒤 BODY로 빠지는 포커스를 수정했다. 마지막 문제는 닫기 순서만 바꾼 첫 시도로 해결되지 않았고, 요청 전 호출 버튼 보존으로 재검증했다. [후속 보고서](../ACCESSIBILITY_FOLLOWUP.md)와 [QA](../QA.md)에 성공·실패·범위를 분리했다.

최종 verify 81/81, 샘플 4/4, 개인 문서 한 영향의 저장/실패/재시도, 이력 복원과 390px를 확인했다. 사용자가 “스크린리더는 여기까지 확인하고 모두 완료로 처리”한다고 명시하여 추가 보조기술 검증을 종료했다. 이는 실제 확인하지 않은 조합을 통과로 바꾸는 결정이 아니다. 독립 참가자 0명, 시간·이해도 향상 수치는 미측정이며 전체 WCAG 판정은 하지 않는다.

## D16 감사 결과를 실제 첫 사용 흐름에 반영

- **시점·권한:** 2026-11-25, 구현 전. 사용자가 D15/X15의 검토 사항을 바탕으로 개선을 요청했다. F01–F11을 기존 Vite/React 앱에 반영한다.
- **근거·대안:** 초안 소실과 안내 불일치가 재현됐고 수동 준비 화면의 단계가 달랐다. 설명을 더 쌓거나 별도 마법사를 만드는 대신, 기존 상태와 저장 경로를 유지하면서 문서 준비를 네 과업으로 나누고 현재 과업만 보여 준다.
- **선택·기대:** 문서/관계 초안도 이탈 보호에 포함, 새 판단은 미선택, 실제 라벨과 안내 일치, 첫 소개에 입출력/수동 범위 명시, 두 예제 완료 경로에 개인 문서 연결을 제공한다. 검토에는 변경 전후·선택 근거를 우선하고 전체 지도는 펼치게 한다. 번역 제목은 원문 변경 없이 항목 필터로 연결한다.
- **대가·불확실성:** 단계 이동/저장 후 초안 기준, 실패 복구, 접근성 초점과 번역 회귀를 검증해야 한다. 보호는 브라우저 이탈 경고이며 자동 DB 저장이나 영구 초안 복원은 추가하지 않는다. 더 쉬운 학습은 아직 가설로, X06/X07의 독립 사람 관찰로 재검토한다.

- **대안·대가:** PLAN은 실제 수행 없이 넘어가는 툴팁 안내와 새 대형 패널의 문제를 설명한다. 현재 선택은 안내 상태·샘플 의존성·좁은 화면 공간을 관리해야 한다.
- **현재 관측·재검토:** 자동화된 브라우저 수행은 성공했다(X03). X06에서 사용자가 완료 후 영향 이유를 설명하지 못하면 단계 수나 안내문보다 개념·사례를 재검토한다.

## D08 샘플에서 개인 문서 첫 검토로 연결

- **원본 시점·권한:** 2026-11-15 PLAN·STATUS·ARCHITECTURE의 개인 문서 경로 기록.
- **선택·당시 근거:** 샘플 완료 후 문서 작성으로 안내하고, 원문 → 항목 → 확정 관계 → 변경의 네 준비 단계를 보여준다. 저장 영수증과 빈 상태는 다음 실제 행동을 가리킨다. [E07·E08·E09](EVIDENCE.md)
- **가정·기대:** 샘플에서 배운 사용법을 자기 자료에 옮길 수 있다. 샘플 개수를 개인 작업의 준비 완료로 오인하지 않게 한다.
- **대안·대가:** PLAN은 새로운 전체 튜토리얼 대신 문맥별 안내를 선택했다고 설명한다. 수동 관계 작성의 난이도와 실제 자료 준비 비용은 여전히 남는다.
- **현재 관측·재검토:** 합성 개인 문서로 저장·0개 영향·관계 확정·검토 복원은 확인되었다. X07에서 사용자가 관계 방향이나 근거 선택에 반복적으로 막히면 그 단계부터 단순화한다.

## D09 영어 기본값과 한국어 인터페이스

- **원본 시점·권한:** ARCHITECTURE는 사용자의 언어 선택 요청을 근거로 기록한다. 2026-11-15 언어 선택 구현 완료 기록 기준이다.
- **선택·당시 근거:** 영어 기본 UI와 기억되는 한국어 선택을 제공하고 원문·인용·사용자 이유는 그대로 둔다. 언어 전환으로 초안과 선택을 잃지 않게 한다. [E07·E09](EVIDENCE.md)
- **가정·기대:** 한국어 사용자의 조작 이해를 돕고 영어 사용도 유지한다. 원문 보존과 화면 번역을 구분한다.
- **대안·대가:** 이전 영어 전용 상태를 확장했다. 번역 카탈로그 유지·긴 레이블·원문과 번역 구분을 계속 확인해야 한다. 다른 접근을 실제 비교한 기록과 소요 시간은 없다.
- **현재 관측·재검토:** 언어 전환·저장·실패 복구는 기존 기록에서 확인된다. 한국어 이해도와 원문 혼동은 X06·X07 대상이다. PLAN의 별도 한국어 샘플 읽기 보조 작업은 기준 수집 당시 진행 중이므로 이 결정의 완료 증거에 합치지 않는다.

## D10 다음 해커톤까지 이어지는 판단 기록

- **시점·권한:** 2026-11-15, 사용자가 현재와 미래 해커톤의 판단·부족한 점을 기록하고 결과 후 분석해 재사용할 것을 요청했다.

- **대가·검증:** 중요한 결정마다 짧은 기록 갱신이 필요하다. 이 작업의 실제 소요 시간은 계측하지 않았다. 링크·발췌·문서 형식 검증 결과는 STATUS에 남긴다.
- **재검토 조건:** 다음 세 번의 중요한 변경에서 사전 기록 여부를 확인한다. 기록이 누락되거나 부담이 크면 결정 양식을 줄인다. 제출 전 원격 보존 여부를 확인하고, 결과 후에는 아래 형식으로 후속 관측을 추가한다.

## D11 첫 경험의 상호작용과 색상 위계 재설계

- **시점·권한:** 2026-11-15, 결정 시점 기록. 사용자는 여전히 무채색·무감정이며 단순 가이드만으로 신규 사용자가 어렵다고 피드백했다. 구체적인 화면 설계는 요청 범위 안에서 AI가 선택한다.
- **관측·불확실성:** 현재 화면에서 안내, 그래프, 변경 비교, 긴 근거가 함께 노출된다. 기존 자동화 성공은 사람의 이해를 검증하지 않았다. 사용자 피드백은 실제 평가이며 신규 사용자 집단의 성공률은 아니다.
- **비교한 대안:** 색만 변경하면 정보 구조가 유지된다. 안내문을 더하면 읽을 양이 늘어난다. 선택한 대안은 첫 진입에서 변경 문장과 실제 영향을 단계적으로 드러내고, 직접 선택한 항목의 근거를 본 뒤 기존 저장 흐름으로 연결하는 것이다.
- **기대·대가:** 첫 행동과 영향의 이유가 더 분명해질 것으로 기대한다. 새로운 첫 화면과 기본 단일 항목 검토 상태를 유지·번역·검증하는 비용이 든다. 실제 작업 시간은 미계측이며 신규 서비스/모델 비용은 없다. 공개 배포와 사용자 모집은 이번 범위에서 진행하지 않는다.
- **검증·재검토:** X11에서 실제 DB 결과·명시적 저장·복원·실패·좁은 화면을 확인한다. 독립 신규 사용자가 영향을 설명하지 못하거나 첫 화면이 오히려 방해되면 X06 관찰 후 구조를 다시 줄인다. 색채 선호와 이해도를 별도로 확인한다.

## D12 Product Design으로 첫 화면·검토 화면 세 방향 비교

- **시점·권한:** 2026-11-15, 생성 전 기록. 사용자가 Product Design을 활용해 첫 화면과 검토 화면의 시안 세 가지를 만들고 비교해 달라고 요청했다. 이번 범위는 시각적 탐색이며 구현 방향은 아직 선택하지 않았다.
- **근거·불확실성:** 현재 두 화면의 실제 캡처를 직접 확인했다. 첫 화면의 설명 면적과 검토 화면의 긴 근거·판단 영역이 다음 행동의 위계를 약하게 만들 수 있다는 설계 가설이 있다. 신규 사용자의 무도움 이해도는 여전히 측정하지 않았다.
- **비교할 대안:** 따뜻한 단계형 체험은 첫 행동에 집중하고, 정돈된 작업대는 근거와 판단의 동시 비교를 지원하며, 연결 중심 지도는 직접·간접 영향의 구조를 우선한다. 단순 색상 변형이 아니라 정보 배치와 상호작용 모델을 비교한다.
- **기대·대가:** 구현 전에 사용자가 선호하는 표현과 작업 방식을 구체적인 두 화면씩으로 비교할 수 있다. 생성 이미지는 실행 가능성·정확한 문구·접근성의 검증 증거가 아니다. 사용자가 요청한 내장 이미지 생성 도구만 사용하며 외부 API 호출·패키지 설치·배포는 범위에 없다.
- **검증·다음 판단:** 세 결과를 실제 확인한 뒤 장점·대가를 비교한다. 원문 보존, 네 영향, 명시적인 유지·수정·보류 판단이라는 제품 조건을 구현 때 다시 확인한다. 선택 이후 코드 구현과 브라우저 검증을 별도 수행하며, 정적 시안만으로 사용성 개선을 주장하지 않는다.

## D13 해커톤 목표에 맞춰 연결 중심 시안을 선택

- **시점·권한:** 2026-11-15, 구현 전 기록. 사용자가 공식 해커톤에 가장 적합한 디자인을 선정하고 진행할 권한을 위임했다. 표시된 3안 Ripple Map을 선택한다.
- **외부 근거:** 같은 날 [공식 안내](https://relate.devpost.com/)와 [규정](https://relate.devpost.com/rules)을 직접 확인했다. 안내는 연결 맥락 30점 등 차등 배점을, 규정은 창의성·유용성·완성도·명료성·연결 맥락의 동일 가중치를 명시해 상충한다. 특정 배점으로 승률을 계산하지 않는다. 두 문서 모두 작동하는 연결 맥락과 재현 가능한 실행을 중시한다.
- **대안·선택:** 1안은 친근한 첫 경험, 2안은 반복 검토, 3안은 변경→결정→작업과 근거의 연결을 가장 직접적으로 보여준다. D12의 첫 사용 우선 추천에서 해커톤 시연이라는 새 목표로 기준이 구체화되었으므로 3안을 택한다. 다른 시안과 혼합하지 않고 선택 이미지의 배치·색상·위계를 구현한다.
- **기대·대가:** 짧은 시연에서 왜 그래프가 필요한지와 왜 해당 작업을 검토하는지 설명하기 쉬워질 것으로 기대한다. 지도·근거·판단의 동기화, 모바일 가독성과 실제 데이터 상태를 검증하는 비용이 있다. 시각적 개선만으로 심사 점수나 초보자 이해 개선을 주장하지 않는다.
- **범위·재검토:** 기존 React/Vite/Relate 구조와 저장 의미를 유지한다. 공개 배포·제출·계정 변경은 포함하지 않는다. 실제 그래프가 작거나 근거/저장이 가려지면 레이아웃을 수정한다. X13에서 구현 검증하고 X06/X07의 사람 관찰은 별도 유지한다.

## D14 시각적 완성도에 대한 사용자 거절 반영

- **시점·근거:** 2026-11-15 구현 전. 사용자가 “디자인이 조금 싼티가 나는 것 같습니다”라고 평가했다. 이번 브라우저 캡처에서 큰 색 면적 여러 개, 색칠된 노드/범례, 작은 보조 문구와 한글 fallback의 불균일한 무게를 확인했다. D13의 기능·시각 비교 통과는 사용자 만족을 입증하지 않았으며 이번 의견이 그 한계를 보여준다.
- **대안·선택:** 새 시안 세 개를 다시 생성하거나 색만 바꿀 수도 있으나, 이미 선택한 연결 중심 흐름은 유지하고 표면·타이포그래피·간격을 정돈한다. 사용자의 이전 무채색 불만도 유지하므로 완전한 흑백화는 하지 않는다. 절제된 petrol 강조, 작은 변경 표식, 밝은 헤더와 원문 중심의 검토 화면을 택한다.
- **기대·대가:** 장식끼리 경쟁하는 정도가 줄고 내용과 선택 경로가 먼저 읽힐 것으로 기대한다. 로컬 한글 글꼴 자산과 라이선스 관리가 추가된다. 미적 수용과 초보자 이해 향상은 사용자가 확인하기 전에는 확정하지 않는다.
- **검증·범위:** X14에서 같은 항목/원문의 전후 화면과 주요 저장 흐름을 확인한다. DB·API·원문·리뷰 의미는 유지한다. 공개 배포·제출·새 에이전트·유료 API는 범위 밖이다.

### D20 실행 후 관측 — 2026-11-26

검토 revision/request ID와 원문 갱신 안내를 실제 구현했다. legacy 이력, retry, ABA, rollback을 포함한 최종 verify 91/91 및 doctor가 통과했고, 실제 두 탭·390px·실패/재시도·원문 v2·4/4·다운로드·프로세스 재시작을 확인했다. 실제 호출자 수정과 심사용 DB 재생성이 필요한 Ripple 사례를 동결했지만, 이를 새로 발견한 누락이나 사용자 효용으로 소급 해석하지 않는다. 자동 준비는 한 실행에서 160ms/21 writes였고 읽기·작성 비용은 미계측이다.
