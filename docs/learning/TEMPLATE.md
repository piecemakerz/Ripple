# 다음 해커톤을 위한 기록 양식

새 프로젝트에서 이 파일을 `docs/learning/README.md`로 복사하고 빈칸을 채운다. 다른 프로젝트의 결과·수치·의사결정을 새 프로젝트의 사실처럼 복사하지 않는다. 기록이 길어지면 결정·실험·회고를 분리하고 서로 연결한다.

## 시작 정보

- 대회 / 프로젝트 / 대상 사용자 / 해결할 구체적인 문제:
- 시작일 / 제출 마감과 시간대 / 공식 규정 출처와 확인일:
- 주최 측 기준과 우리의 해석 / 서로 상충하는 안내:
- 가용 시간·예산·팀 역할 / 필수 제약 / 이번 범위에서 제외할 것:
- 이미 가진 자산과 재사용 고지 / 신규 구현 범위:
- 핵심 가치 가설 / 가장 위험한 가정 / 가장 먼저 확인할 반례:
- 제출물과 완료 증거 / 실제 성공을 무엇으로 판단할지:
- 기록 담당과 비공개 자료 보관 원칙:

## 중요한 결정 하나당 남길 내용

- **D ID / 결정일 / 기록일 / 결정 시점 기록 또는 사후 복원:**
- **권한·역할:** 사용자 명시적 선택 / 위임 범위의 AI 선택 / 제안만 한 상태. 실제 결정자와 근거 위치.
- **문제와 제약:** 지금 무엇을 결정해야 하는가.
- **당시 정보:** 확인한 사실·출처·모르는 점. 원문과 해석을 구분.
- **실제 비교한 대안:** 2–3개 또는 비교하지 못한 이유. 검토하지 않은 대안을 사후에 꾸며 넣지 않음.
- **선택과 이유 요약:** 가장 중요한 근거와 수용한 대가.
- **예상 결과·확신:** 어떤 행동·관측이 나타날 것인가. 수치의 근거가 없으면 정성 기준.
- **비용과 기회비용:** 예상 시간·비용, 미루는 작업, 실제 측정 계획.
- **반증·재검토 조건:** 어떤 결과가 나오면 선택을 바꿀 것인가. 관련 X ID.
- **후속 관측:** 새 날짜로 결과·차이·유지/수정/보류·다음 D ID를 추가. 기존 예측은 보존.

## 실험 하나당 남길 내용

- **X ID / 관련 D ID / 설계일 / 상태:** 계획·실행 중·완료·중단·미실행.
- **가설과 반대 가설:**
- **대상과 표본:** 사용자/AI/개발자, 참가자 수·모집 방식·친숙도.
- **자료·제품 버전:** 데이터 출처, 정답 판정자, 커밋과 미커밋 여부.
- **방법·비교 조건:** 시작/끝 정의, 순서·학습 효과·도움, 준비 비용.
- **실행 전 판정 기준:** 성공·실패·보류를 어떻게 구분하는가.
- **실제 결과:** 수치·원문 발언·관찰·오류·실패·중단을 원자료와 연결.
- **해석과 한계:** 직접 관측한 사실, 가능한 설명, 반례, 일반화할 수 없는 범위.
- **다음 행동:** 결정 유지·수정·폐기·추가 확인.

## 근거 하나당 남길 내용

`E ID / 작성자 또는 관찰자 역할 / 사건일 / 수집일 / 원문 위치·버전 / 짧은 발췌 / 사실과 해석 / 보관·공개 범위 / 관련 D·X ID`

원본이 변할 수 있으면 승인된 범위의 사본·버전·해시를 남긴다. 해시만으로 원문을 복원할 수 없다는 점을 기억한다. 비밀·개인정보·비공개 피드백은 공개 저장소에서 제외한다.

## 작업 종료 때 추가할 기록

`날짜 / 연결 D·X ID / 한 일 / 실제 확인·실패·미실행 / 예상 대비 차이 / 실제 시간·비용 또는 미계측 / 미룬 일 / 다음 가장 중요한 확인`

테스트 통과는 제품 수요가 아니고, 클릭 완료는 이해가 아니며, AI 평가는 독립 사람 검증이 아니다. 실제 실행하지 않은 검사는 미실행으로 적는다.

## 제출본 고정

- 코드 커밋과 미커밋 변경 / 데이터·사례 버전:
- 최종 설명·영상·데모·자료의 URL 또는 보관본:
- 당시 규정·평가 기준 / 자격·필수 제출물 확인:
- 로그인 없는 접근·새 환경 실행 / 실패와 해결:
- 제출 일시·접수 확인 증거:
- 결과를 보기 전 기대·강점·미해결 위험:

## 결과 후 회고

1. 공식 결과·발표일·피드백 원문을 확보한다. 수상, 미수상, 미제출, 접수 문제, 결과 미확인을 구분한다.
2. 각 D ID의 당시 정보·예상과 실제 결과를 나란히 놓는다. 사후 설명으로 원래 예측을 덮어쓰지 않는다.
3. 문제 선택·가정·검증·구현·전달·제출·외부 요인을 분리한다. 원인 후보마다 지지 증거·반대 증거·다른 설명·당시 통제 가능성을 적는다.
4. 공식 기준과 동일한 항목으로 다른 제출작을 비교한다. 공개된 특징만으로 수상 원인을 단정하지 않는다.
5. 유지·수정·폐기·보류를 정하고, 다음 대회에서 적용할 규칙을 최대 세 개 고른다. 조건·예외·실행 시점·확인 지표를 포함한다.
6. 다음 대회에서 이전 규칙의 실제 적용과 효과를 확인한다. 미수상을 사고 오류의 증명으로, 수상을 모든 결정의 정당화로 쓰지 않는다.

## 여러 대회에서 이어갈 학습 목록

| 대회·프로젝트 | 결과·근거 | 배운 규칙·근거 | 적용 조건·예외 | 다음 프로젝트에서 실행·관측한 결과 | 유지·수정·보류 |
| ------------- | --------- | -------------- | -------------- | ---------------------------------- | -------------- |
| 작성 전       | 미확인    | 미확인         | 미확인         | 미실행                             | 보류           |

각 대회의 기록 링크를 승인된 개인 보관 장소의 목록에 모은다. 다음 프로젝트 시작 시 관련 규칙 1–3개를 가져와 다시 검증한다. 이 파일 복사만으로 전체 프로젝트의 자동 수집·원격 백업이 구성되지는 않는다.

## 새 프로젝트 AGENTS에 넣을 지침

```markdown
## Hackathon learning record

- Read docs/learning/README.md at the start of substantive work.
- Before material product, scope, technology, schedule or submission decisions,
  record dated rationale summaries, actual alternatives, expected outcomes,
  costs, uncertainty and reconsideration criteria in that learning record.
- Distinguish user decisions, delegated AI choices and proposals; link evidence.
- Preserve prior predictions. Append dated outcomes, corrections and reversals.
- Separate observed facts, hypotheses, AI evaluations and human feedback.
- Record failed/unrun checks honestly. Never invent past reasoning or time spent.
- At handoff, link actual verification, remaining risks and the next experiment.
- Freeze the actual submission before results; compare it with feedback afterward.
- Keep private evidence and credentials out of public records. Follow existing
  authorization for publication, messaging, paid services and submission.
```

## 다음 대회를 시작할 때 사용할 요청

```text
이 프로젝트에 해커톤 판단과 학습 기록을 적용해주세요.
기존 AGENTS와 제품 문서, docs/learning/README.md를 읽고,
이전 대회의 적용 가능한 교훈은 [기록 위치]에서 확인해주세요.
중요한 선택 전에 근거·실제 대안·예상·비용·재검토 조건을 기록하고,
작업 후 실제 검증과 예상의 차이를 덧붙여주세요.
미기록 과거 판단은 꾸며내지 말고, 사후 복원과 결정 시점 기록을 구분해주세요.
결과 발표 후 제출본·피드백·경쟁작의 확인 가능한 증거를 비교해
다음 대회에서 시험할 규칙까지 연결해주세요.
```
